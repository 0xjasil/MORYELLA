## 2. Design System — Tokens & Rules

> **Skillui extraction:** `SKILL.md` and `DESIGN.md` at the project root are auto-generated by skillui v1.3.4 from the live codebase. They are the authoritative token reference. `CLAUDE.md` provides the agent context entry point. Read `SKILL.md` before writing any CSS or Tailwind classes.

All visual values live in `styles/globals.css` as CSS custom properties. **Never hard-code hex values or pixel sizes in component code.** Always use a token.

### Color palette (60-30-10 rule)

| Token | Value | Role |
|---|---|---|
| `--color-bg` | `#FAF8F3` | 60% — page background (warm cream) |
| `--color-text-primary` | `#0C1014` | 30% — headings, body text |
| `--color-accent` | `#D25C40` | 10% — CTAs, badges, links |
| `--color-surface` | `#FFFFFF` | Card / input backgrounds |
| `--color-border` | `#E5E0D8` | Dividers, card borders |
| `--color-text-secondary` | `#555555` | Subtitles, metadata |
| `--color-surface-warm` | `#FFF5F0` | Discount pill backgrounds |

### Spacing scale

Tokens run `--space-1` (1 px) through `--space-17` (48 px). Map rough intent:

| Intent | Token |
|---|---|
| Tight padding (icon, badge) | `--space-2` / `--space-3` |
| Card internal padding | `--space-3` / `--space-4` |
| Section horizontal gutter | `--space-6` (10 px) |
| Card gap in grid | `--space-4` (5 px) |
| Section vertical rhythm | `--space-8` (12 px) |

### Elevation

`--shadow-sm` → `--shadow-xl` (4 levels). Cards rest at `shadow-sm`, hover at `shadow-md`. Modals use `shadow-xl`.

### Border radius

All radius tokens resolve to `4px` (sharp-modern). Do not introduce rounded-full on rectangles.

### Typography

Font stack: `Inter, Source Sans Pro, sans-serif`. No external font imports yet — system fonts only.

## 3. Component Catalogue

Each component has a clear single responsibility. New components must fit one of these roles.

### 3.1 Layout primitives

| Component | File | Responsibility |
|---|---|---|
| `Header` | `components/Header.tsx` | Sticky top bar — announcement, logo, nav, search, login modal, cart |
| `Footer` | `components/Footer.tsx` | Links, app CTAs, social icons, legal |

**Rules for Header:**
- Always sticky (`sticky top-0 z-50`)
- Cart badge count comes from cart context (to be wired when cart state is lifted)
- Search bar expands on demand — do not render a second search input if one is already visible
- Login modal is self-contained; use `z-[100]` to sit above header

### 3.2 Section components

| Component | Responsibility |
|---|---|
| `Hero` | Full-width hero banners (first paint — must be fast) |
| `ProductGrid` | Main product catalog grid with category filter tabs |
| `ProductSections` | Secondary themed rows (Health & Wellness, Gifting) |
| `BrandSpotlight` | Brand logo/card carousel |
| `PromoGrid` | Editorial banners and curated offer cards |

**Rules for sections:**
- Every section is `<section>` with `mx-auto max-w-7xl px-[var(--space-6)]`
- Section heading: `text-2xl font-bold text-[var(--color-text-primary)]`
- Section subheading: `text-sm text-[var(--color-text-secondary)]`
- Never exceed `max-w-7xl` — the layout is fixed-max-width centred

### 3.3 Product card (reusable pattern)

The product card pattern is used in `ProductGrid`, `ProductSections`, and `category/[...slug].tsx`. It is NOT yet extracted into its own component — **when you extract it, name it `ProductCard.tsx`** and place it in `/components`.

Product card anatomy:
```
<Link href="/product/{id}">
  <div> ← outer shell: rounded, bg-white, shadow-sm, hover:shadow-md
    <div> ← image container: aspect-square, overflow-hidden, bg-white, p-2
      <img object-contain>
      <badge> ← absolute positioned, top-left
    </div>
    <div> ← info: p-3
      brand (10px, uppercase, secondary)
      name (xs, line-clamp-2, primary)
      price row (price + strikethrough original + discount %)
      rating row (★ + rating + count)
    </div>
    <div> ← CTA: p-3, pt-0
      "Add to Bag" button (outline → filled green on add)
    </div>
  </div>
</Link>
```

### 3.4 Button primitive

`components/Button.tsx` — reusable, accepts `variant` (`primary` | `outline` | `ghost`) and `size` (`sm` | `md` | `lg`). All new buttons must use this component or this pattern.

| Route | File | Purpose |

| `/` | `pages/index.tsx` | Homepage — composed sections |
| `/product/[id]` | `pages/product/[id].tsx` | Product detail page |
| `/category/[...slug]` | `pages/category/[...slug].tsx` | Category listing |

### URL conventions

- Categories: `/category/skincare`, `/category/makeup`
- Products: `/product/{id}` where `id` is a string matching `Product.id`
- All slugs are lowercase, spaces replaced with hyphens

### Breadcrumb rule

All inner pages (product, category, cart) must render a breadcrumb:
```
Home > Category > Product Name
```
Use `text-xs text-[var(--color-text-secondary)]` with `hover:underline` on links.

## 6. Data Layer

### Current (static JSON)

- `products.json` → imported in `ProductGrid.tsx`, exported as `products` array, imported by product and category pages
- `banners.json` → imported directly in `pages/index.tsx`

**All data reads are synchronous — no loading states needed currently.**

### Future API migration path

When moving to a real backend:

1. Create `lib/api.ts` with typed fetch helpers:
   ```ts
   export async function getProducts(filters?: ProductFilters): Promise<Product[]>
   export async function getProduct(id: string): Promise<Product>
   export async function getBanners(): Promise<Banner[]>
   ```
2. Use `getStaticProps` / `getServerSideProps` in page files — do NOT fetch in components
3. Add loading skeletons matching product card dimensions before real data is available
4. Keep `products.json` as the fallback/seed data

### API endpoint conventions (future backend)

```
GET  /api/products            → Product[]
GET  /api/products/:id        → Product
GET  /api/products?category=  → Product[] (filtered)
GET  /api/banners             → Banner[]
POST /api/cart                → Cart session
GET  /api/cart/:sessionId     → CartItem[]
POST /api/orders              → Order
```

## 7. Performance Rules

Every change must respect these constraints:

1. **Images** — always use `object-contain` (`.banner-contain`, `.product-contain` CSS classes). Never use `object-cover` for product images. Add `loading="lazy"` to all images below the fold.
2. **Hero images** — the first hero image should use `loading="eager"` (or omit loading attribute) since it's above-the-fold.
3. **Grid layouts** — use CSS Grid, not Flexbox, for product grids. Use `grid-cols-2 sm:grid-cols-3 md:grid-cols-4 lg:grid-cols-6` as the standard product grid breakpoint ladder.
4. **Horizontal scrollers** — use `overflow-x-auto no-scrollbar flex` with `flex-shrink-0` children. Never hide scrollbars with visibility:hidden.
5. **Avoid layout shift** — product images use `aspect-square` container; banner images use explicit aspect ratio wrappers.
6. **No unused imports** — clean up any import not referenced in the file.

---

## 8. Accessibility Rules

1. All interactive elements (`<button>`, `<a>`) must have either visible text or `aria-label`
2. Images must have meaningful `alt` text — fall back to `banner.title || banner.alt || "product image"`
3. Search input: `aria-label="Search products and brands"` (already in Header — maintain it)
4. Modal focus trap: when Login modal is open, focus should be trapped inside
5. Color contrast: `--color-accent` (#D25C40) on white passes WCAG AA for large text only — do not use it for body text smaller than 18px
6. Cart icon badge: wrap count in `<span aria-label="{n} items in cart">`

## 9. Scalability Patterns

### 9.1 Adding a new page

1. Create `pages/new-page.tsx`
2. Import `Header` and `Footer` — wrap content in `<main>`
3. Add breadcrumb if it's an inner page
4. Use `mx-auto max-w-7xl px-[var(--space-6)]` as the content wrapper
5. Use `py-[var(--space-8)]` vertical padding

### 9.2 Adding a new section to the homepage

1. Create `components/NewSection.tsx`
2. Export a default function named after the file
3. Keep it self-contained (data can be passed as props or imported)
4. Add it between existing sections in `pages/index.tsx`
5. Wrap in `<section>` with correct max-width and gutter

### 9.3 Adding a new product category

1. Add category string literal to the `Product["category"]` union in `ProductGrid.tsx`
2. Add the category slug to `mainCats` array in `Header.tsx`
3. Add the category to the footer section "Top Categories" in `Footer.tsx`
4. Category pages work automatically via `[...slug].tsx` — no new page needed

### 9.4 Adding a new banner section to the homepage

1. Determine the `banner-{n}` ID range from `banners.json`
2. Add a filter constant in `pages/index.tsx` following the existing filter pattern
3. Render the section using the appropriate grid or scroll pattern (see existing sections)

## 11. Code Conventions

### File naming
- Components: `PascalCase.tsx`
- Pages: `kebab-case.tsx` (Next.js convention) or `[param].tsx`
- Utilities/lib: `camelCase.ts`
- Context: `PascalCaseContext.tsx`

### Component structure (order within file)
```ts
// 1. React + Next.js imports
// 2. Third-party imports
// 3. Internal component imports
// 4. Internal data/util imports
// 5. Types/interfaces
// 6. Constants (arrays, objects outside component)
// 7. Component function
// 8. Export default
```

### Tailwind class order
Follow: layout → flexbox/grid → sizing → spacing → typography → color → border → shadow → transition

### TypeScript rules
- No `any` in new code — use proper types or `unknown` + type guards
- Export interfaces used across multiple files from a shared `types/index.ts` (create when needed)
- Props interfaces: `interface ComponentNameProps { ... }`

### Comments
- Inline comments only for non-obvious logic
- Section separators in complex pages: `{/* ── Section Name ─────────── */}`

## 13. Do Not / Never List

These are hard rules. The agent must never do these:

1. **Never hard-code hex colors** — always use a `--color-*` token
2. **Never use `object-cover` on product images** — always `object-contain`
3. **Never fetch data inside a component** — data fetching belongs in `getStaticProps`, `getServerSideProps`, or a `useEffect` + context
4. **Never import from `pages/` inside `components/`** — components cannot depend on pages
5. **Never push directly to `main`** — always use a feature branch
6. **Never add a new font without removing or consolidating** — one font stack only
7. **Never exceed `max-w-7xl`** for any content container
8. **Never use inline styles for design values** — use Tailwind classes or CSS tokens
9. **Never create a component that cannot be reused** — if it's only used once and is trivial, keep it inline
10. **Never skip the breadcrumb** on inner pages (product, category, cart)

## 14. Quick Reference — Patterns

### Standard section shell
```tsx
<section className="mx-auto max-w-7xl px-[var(--space-6)] py-[var(--space-8)]">
  <div className="mb-[var(--space-6)]">
    <h2 className="text-2xl font-bold text-[var(--color-text-primary)]">Title</h2>
    <p className="mt-1 text-sm text-[var(--color-text-secondary)]">Subtitle</p>
  </div>
  {/* content */}
</section>
```

### Standard product grid
```tsx
<div className="grid grid-cols-2 gap-[var(--space-4)] sm:grid-cols-3 md:grid-cols-4 lg:grid-cols-6">
  {products.map(p => <ProductCard key={p.id} product={p} />)}
</div>
```

### Standard horizontal scroll strip
```tsx
<div className="flex items-center gap-4 overflow-x-auto no-scrollbar py-1">
  {items.map(item => (
    <div key={item.id} className="flex-shrink-0 ...">...</div>
  ))}
</div>
```

### Standard modal
```tsx
<div className="fixed inset-0 z-[100] flex items-center justify-center bg-black/50">
  <div className="w-full max-w-md rounded-[var(--radius-xl)] bg-[var(--color-bg-white)] p-[var(--space-8)] shadow-[var(--shadow-xl)]">
    {/* modal content */}
  </div>
</div>
```

### "Add to Bag" flash state pattern
```tsx
const [added, setAdded] = useState(false);
const handleAdd = () => {
  setAdded(true);
  setTimeout(() => setAdded(false), 2000);
};
<button onClick={handleAdd}>
  {added ? "✓ Added to Bag" : "Add to Bag"}
</button>
```
